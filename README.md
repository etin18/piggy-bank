# 存錢筒

記錄 ETF 與基金的買賣、配息和資金進出，資料存在自己的 Google 試算表裡。
手機優先，可以加到主畫面像 App 一樣開。

- **記錄** — 選 ETF 或基金，再選買進／賣出／配息／入金出金
- **報表** — 今年累積配息、平均每月、每月長條圖、兩個帳戶餘額
- **持股** — 一檔一列，只顯示「賺賠多少」；點開才看損益拆解

金額一律台幣。ETF 是台股，基金是台幣計價（計價幣別 TWD、匯率 1），整個 App 沒有匯率換算。

完整的需求討論記錄在 [需求規格.md](需求規格.md)。

---

## 第一次設定（三步）

### 1. 建一份 Google 試算表

隨便開一份新的試算表，名字自己取，例如「存錢筒」。五個分頁（標的、交易、配息、資金、現價）
會在第一次連線時自動建好，不用先做任何事。

### 2. 部署後端

1. 在那份試算表裡：**擴充功能 → Apps Script**
2. 把 [google-apps-script/Code.gs](google-apps-script/Code.gs) 整份貼上
3. **把最上面的 `SECRET` 改成自己的一組密語**，例如 `piggy2026kk`
4. 存檔 → **部署 → 新增部署作業 → 網頁應用程式**
   - 執行身分：**我**
   - 具有存取權的使用者：**任何人**
5. 過程中會要求授權，其中一項是**連線至外部服務** —— 那是用來抓台股報價的，要同意
6. 複製產生的網址（結尾是 `/exec`）

> 之後如果更新了 `Code.gs`，要**重新部署**（部署 → 管理部署作業 → 編輯 → 版本選「新版本」）
> App 才會用到新版。加了新權限的版本還會再要求授權一次。

> ⚠️ 改好密語的那份程式只存在你自己的 Apps Script 編輯器裡。
> **不要**把含真實密語的版本貼回 GitHub —— 那等於把鑰匙公開。
> 裡面是你的持股和金額。

### 3. 在 App 裡填進去

開啟 App → 右上角齒輪 → 貼上網址和**同一組**密語 → 儲存並測試。
右上角出現「已同步」就成功了。

手機上用 Safari 開，分享 → 加入主畫面，之後就像一般 App 一樣開。

## 日常怎麼記

**買進（ETF）** — 選 ETF → 買進 → 填數量（可切「張」或「股」）和成交價，
金額和帳戶實扣會自動算好，對照券商畫面改一下就好。

**買進（基金・台幣計價）** — 欄位順序照銀行對帳單排：申購金額 → 淨值 → 單位數。
三個數字直接抄，單位數會自動算但抄的最準。手續費選填。

**買賣（基金・美元計價）** — 欄位改成照申購／贖回通知單排：
單位數 → 淨值(美元) → 結匯匯率 → 台幣金額。填完淨值會即時顯示原幣金額，
台幣金額和帳戶實收都自動算：

```
0.4950 單位 × USD 200.58 ＝ USD 99.29
USD 99.29 × 31.5750 匯率 ＝ TWD 3,135     ← 對帳單的「入帳淨額」
```

成本與損益一律用換匯後的台幣金額算。

**配息** — 填發放日、每單位配息、實領金額。持有單位會依除息日自動帶入，
應發金額和被扣掉的稅費會即時顯示，可以順便核對數字有沒有填錯。
基金要選是「單筆」還是「定期定額」的配息（銀行分開發，帶入的持有單位也會跟著換）。

**入金出金** — 存錢或領錢進出帳戶時記一筆，帳戶餘額才對得起來。

**2025 之前的部位** — 交易表單上勾「2025 之前（期初持有）」，
填當時的累積數量和成本。這筆不列入任何月份統計，也不扣帳戶餘額
（那筆錢在期初餘額被填進來之前早就付掉了），只讓持有數量和平均成本正確。

**看持股** — 一檔一列，收合時只有「名字 ＋ 賺賠多少（含息）」，一個畫面掃得完。
點開才展開損益拆解：

```
投入 $33,380  →  現值 $35,302
價格漲跌      −$1,485    −4.4%
領到的配息    +$4,892
────────────────────────
合計          +$3,407   +10.2%
```

價格在跌、配息把它補回來還有賺 —— 這種狀況拆開才看得懂，
兩個顏色相反的數字並排只會讓人困惑。

**看單一檔的紀錄** — 展開後點「所有紀錄 ›」，會列出那一檔的所有買賣與配息，
可以只看買賣或只看配息，點任一筆直接編輯。已出清的標的一樣點得進去。

**調整顯示的資訊** — 展開後那行小字（平均成本、淨值、匯率）要顯示哪些可以自己勾
（持股頁右上角的按鈕）。設定只存在該台裝置，不會寫進試算表。

**現價（ETF 自動）** — 到「持股」按一下「更新 ETF 現價」，會從證交所抓回持有中的每一檔。
盤中拿到的是最新成交價（延遲約 20 秒），盤前、盤後、假日則是最近一個交易日的收盤價。
單檔也可以在現價表單裡按「自動抓取」。前提是標的有填代號。

**現價（基金手動）** — 基金沒有公開的淨值 API，一樣在「持股」點該檔右下角的按鈕，
把對帳單上的淨值抄進去。

**美元計價的基金** — 有些基金用台幣扣款，但**淨值是美元**（對帳單上會有「參考匯率」
之類的欄位，不是 1.0）。這種要在標的設定裡把「計價幣別」選成美元，
更新淨值時連同對帳單上的參考匯率一起填：

```
市值 ＝ 單位數 × 淨值(美元) × 匯率
```

沒設成美元的話，市值會少算 30 倍。填的時候表單下方會即時試算市值，跟對帳單的
「參考現值」對一下就知道有沒有填錯。

沒填現價的那檔，市值會先用成本計算，報表會提醒你。

## 數字是怎麼算的

**部位怎麼分**

- ETF：一檔一個部位
- 基金：一檔分「單筆」和「定期定額」**兩個部位**，各自算成本 ——
  銀行本來就是分開的兩筆投資明細，各有各的平均淨值，配息也分開發

**持有回合**

每個部位的交易依時間切成一段一段的「回合」，**持股歸零就結束一段**，
下次買進開新的一段、成本從零重新算。賣光之後買回來的那批，成本跟賣掉的那批無關。

已出清的回合留在持股頁下方的「已出清」區，各自記著那段期間的已實現損益與配息。
同一檔進出三次就有三段。

**平均成本（移動加權平均法）**

```
平均成本 ＝ 這一段的買進金額累計 ÷ 買進數量累計
```

賣出時按當下的平均成本扣掉對應成本，所以部分賣出不會改變平均成本。
持股頁顯示的「平均成本」不含手續費，跟券商、銀行對帳單一致。

**手續費**：算進投入成本，但不影響部位價值。

```
累計投入   ＝ 買進金額 ＋ 手續費
市值       ＝ 持有數量 × 最新價格 × 匯率（台幣計價的匯率是 1）
未實現損益 ＝ 市值 − 持有部位成本（含手續費）
含息報酬   ＝ 市值 − 持有部位成本 ＋ 累計配息
已實現損益 ＝ 賣出實收 − 賣出部位的平均成本
```

「含息報酬」對應對帳單上的「參考損益」，是把領到的配息也算進去的總成果。
持股卡片上方那個大數字則是不含配息的未實現損益。

**帳戶餘額**（兩個帳戶各算各的）

```
餘額 ＝ 期初 ＋ 存入 − 提領 ＋ 賣出實收 ＋ 配息實領 − 買進實扣
```

**配息統計**（依發放日歸月）

```
今年累積 ＝ 發放日落在今年的實領總和
平均每月 ＝ 今年累積 ÷ 今年已過月數
```

去年以前的年份除以 12。ETF 和基金分開統計，另給合計。

## 資料表

| 分頁 | 內容 |
|---|---|
| 標的 | 代號、名稱、類型、配息頻率、狀態 |
| 交易 | 日期、標的、動作、型態、數量、單價、金額、手續費、帳戶金額 |
| 配息 | 除息日、發放日、標的、每單位配息、持有單位、實領金額 |
| 資金 | 日期、帳戶、動作、金額 |
| 現價 | 標的、價格、更新時間 |

日期欄的 `PRE2025` 代表「2025 之前」的期初。

資料可以直接在試算表裡改，App 下次同步就會讀到。反過來也一樣 ——
App 的每筆變更會先寫進手機本機（畫面立刻更新），再排隊送上試算表；
沒網路時留在佇列裡，有網路自動補送。

## 部署到 GitHub Pages

推到 `main` 就會自動部署 `www/` 資料夾（見 [.github/workflows/deploy.yml](.github/workflows/deploy.yml)）。
第一次跑會自動開啟 Pages，網址在 Actions 的部署結果裡。

改過 `www/` 裡的檔案，記得把 [www/sw.js](www/sw.js) 最上面的 `VERSION` 加一號，
否則手機會一直吃舊快取看不到新版。

## 開發

```bash
# 本機開發伺服器（不走快取，改了檔案重整就看得到）
python3 scripts/serve.py          # http://localhost:8789

# 重新產生 PWA 圖示
node scripts/make-icons.js

# 驗證台股報價的抓取與解析（不需要 server，直接連證交所）
node scripts/test-quotes.js [代號…]

# 版面實測 + 數字驗算（需要本機 server 開著）
PW_CORE=<playwright-core 路徑> node scripts/screenshot.js

# 底部面板下拉關閉手勢（用 CDP 送真觸控事件）
PW_CORE=<playwright-core 路徑> node scripts/test-sheet-drag.js
```

`screenshot.js` 會灌入一份手算過的假資料（含期初概估、定期定額、季配與月配），
走完主要流程，比對平均成本、帳戶餘額、配息統計等數字，
在淺色與深色下截圖到 `shots/`，並回報 JS 錯誤。
